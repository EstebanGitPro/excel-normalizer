Cómo se arma la hoja SALDO TERCERO

Explicación del método SaldoTerceroSheet.write y de writeDerivedFormulas: qué hace cada línea, de dónde vienen los datos y a dónde van.

0. Aclaración 1. Como si fueras un niño 2. Diagrama 3. write() línea por línea 4. writeDerivedFormulas línea por línea 5. Ejemplo con una fila real

0. Aclaración importante antes de empezar

Los dos fragmentos que pegaste vienen de archivos distintos:

  • write(...) es de SaldoTerceroSheet.java.
  • El writeDerivedFormulas con "E" y LEN es de MayorSheet.java.

Cada hoja tiene su propio writeDerivedFormulas (es private, solo lo ve su clase). La idea es la misma, pero cambian dos cosas:

MayorSheetSaldoTerceroSheet
Columnas derivadasLARGO, N1, N2, N3 (4)N1, N2, N3 (3)
Dónde queda el código de cuentacolumna Ecolumna D
FórmulasLEN, LEFT 1, LEFT 2, LEFT 4LEFT 1, LEFT 2, LEFT 4

¿Por qué E en una y D en la otra? El código de cuenta es siempre la primera columna copiada. Si delante hay 4 columnas derivadas (A, B, C, D), el código cae en la E. Si hay 3 (A, B, C), cae en la D.

1. Como si fueras un niño

Imaginá que tenés un cuaderno viejo (el Excel que exporta el sistema contable) y te piden pasarlo en limpio a un cuaderno nuevo.

  1. Primero mirás la primera página para saber en qué columna está cada cosa: "el NIT está en la columna 5, el código en la 1…". Eso hace Cells.headerIndex.
  2. Preparás dos marcadores: uno rojo y uno negro. Eso hace styles.red(...) y styles.plain(...).
  3. Copiás renglón por renglón. Antes de escribir cada renglón te hacés una pregunta: "¿este renglón tiene NIT?"
    • Si no tiene NIT, es un total de la cuenta → agarrás el marcador rojo.
    • Si sí tiene NIT, es una persona o empresa → agarrás el marcador negro.
  4. Con ese mismo marcador escribís todo el renglón:
    • Primero tres cajitas al principio (N1, N2, N3), que son pedacitos del código: el primer número, los dos primeros y los cuatro primeros.
    • Después copiás lo demás: código, nombre, NIT, saldos…

¿Cuál era el error de antes? El niño escribía las tres cajitas antes de elegir el marcador, con un lápiz cualquiera. Después agarraba el rojo y seguía con el resto. Por eso el renglón quedaba rojo desde la cuarta cajita y no completo.

El arreglo: primero elegís el marcador y después escribís todo el renglón con él.

4. writeDerivedFormulas línea por línea

Este es el que pegaste, de MayorSheet.java. Abajo está la diferencia con el de SALDO TERCERO.

CódigoQué hace / de dónde viene / a dónde va
private static void writeDerivedFormulas( Row row, CellStyle style) private: solo lo usa esta clase. static: no necesita datos del objeto, todo lo recibe por parámetro.
Recibe: la fila nueva (targetRow) y el estilo ya decidido (style.text()).
int excelRow = row.getRowNum() + 1; Clave: POI cuenta las filas desde 0 y Excel desde 1. La fila 4 de POI es la 5 de Excel, por eso se suma 1.
String codctaRef = "E" + excelRow; Arma la referencia a la celda del código de cuenta en esta misma fila, por ejemplo "E5". En SALDO TERCERO es "D" + excelRow.
String[] formulas = { "LEN(" + codctaRef + ")", "LEFT(" + codctaRef + ",1)", "LEFT(" + codctaRef + ",2)", "LEFT(" + codctaRef + ",4)"}; Un arreglo de 4 textos con las fórmulas. Para la fila 5 quedan:
  • LEN(E5): cuántos caracteres tiene el código. Es LARGO en Excel en español.
  • LEFT(E5,1): el primer dígito, la clase (N1). Es IZQUIERDA en español.
  • LEFT(E5,2): los 2 primeros, el grupo (N2).
  • LEFT(E5,4): los 4 primeros, la cuenta (N3).
Las fórmulas se escriben en inglés en el código, porque así las guarda el archivo .xlsx. Excel las traduce al abrirlo.
for (int c = 0; c < formulas.length; c++) { Una vuelta por cada fórmula. c es a la vez el índice de la fórmula y el de la columna: 0 = A, 1 = B, 2 = C, 3 = D.
Cell cell = row.createCell(c); Crea la celda en la columna c de la fila nueva.
cell.setCellFormula(formulas[c]); Guarda la fórmula, no un resultado. El cálculo lo hace Excel cuando abre el archivo. Por eso se escribe sin el = del principio.
cell.setCellStyle(style); Esta es la línea que faltaba. Sin ella, las celdas A a D quedaban sin estilo, sin color ni bordes. Ahora toman el mismo estilo que el resto de la fila.

La versión de SALDO TERCERO (líneas 98–110)

private static void writeDerivedFormulas(Row row, CellStyle style) {
    int excelRow = row.getRowNum() + 1;
    String codeRef = "D" + excelRow;          // ← D, no E
    String[] formulas = {
            "LEFT(" + codeRef + ",1)",        // N1  (antes era LEN)
            "LEFT(" + codeRef + ",2)",        // N2
            "LEFT(" + codeRef + ",4)"};       // N3
    for (int c = 0; c < formulas.length; c++) {
        Cell cell = row.createCell(c);
        cell.setCellFormula(formulas[c]);
        cell.setCellStyle(style);
    }
}

5. Ejemplo con dos filas

Supongamos que el Excel de origen trae estas dos filas, que van a quedar en las filas 5 y 6 del Excel nuevo:

  • Fila 5: Código 110505, Nombre "Caja general", NIT vacío, Saldo final 1.500.000.
  • Fila 6: Código 110505, Nombre "Caja general", NIT 900123456, Saldo final 1.500.000.

Paso a paso para la fila 5:

  1. Línea 66: nit = null, porque la celda está vacía.
  2. Línea 67: nit == null es verdad, así que style = subtotal (rojo).
  3. Línea 68: se escriben A5 = LEFT(D5,1), B5 = LEFT(D5,2) y C5 = LEFT(D5,4), las tres en rojo.
  4. Líneas 69–75: se copian los datos de D5 a K5, también en rojo.

Resultado en Excel:

A · N1B · N2C · N3D · CódigoE · NombreF · NIT…K · Saldo final
51111105110505Caja general…1,500,000.00
61111105110505Caja general900123456…1,500,000.00

La fila 5 queda roja de punta a punta, de A a K. Antes del arreglo, A, B y C quedaban sin color ni bordes.
